## 1. 背景与问题

PinBoard v1 定位为**通用置顶文本钉板**，核心链路"点标题 → 整块复制 → 切网页粘贴"已跑通。但产品的真实核心场景是**网申填简历**：用户在网申系统逐字段填写表单时，需要随时查看并复制自己的简历信息。

当前产品与该场景存在结构性错位：

| # | 错位点  | 现状                                        |
| - | ---- | ----------------------------------------- |
| 1 | 复制粒度 | 表单要"单字段"（手机号、邮箱、绩点），产品只支持整块复制，填单字段需手动选中文本 |
| 2 | 信息组织 | 简历拆成字段后块数量 30+，平铺无搜索，定位靠肉眼翻找              |
| 3 | 录入成本 | 逐块"新建 → 粘贴 → 命名"，准备 30 个字段要点 30 次         |
| 4 | 开箱体验 | 默认模板（Git/Docker/SSH）面向开发者，与网申人群画像不符       |
| 5 | 隐私暴露 | 置顶 = 手机号、身份证等敏感信息长期裸露屏幕，截屏/投屏即泄露          |
| 6 | 盲填风险 | 网申表单普遍有字数限制，用户贴入前无法判断长度是否超限               |

---

## 2. 目标与非目标

### 2.1 目标

1. **压缩核心循环**：任意一个字段的"找到 → 复制"操作 ≤ 2 次点击。
2. **降低录入门槛**：首次启动 10 分钟内完成一份可用的简历字段录入。
3. **保持产品气质**：轻量、离线、置顶不干扰，不因新功能膨胀。

### 2.2 非目标（范围红线）

- ❌ 不做剪贴板历史管理器（Windows 已内置 `Win+V`）
- ❌ 不做浏览器自动填表 / 表单识别（AutoFill 是独立产品）
- ❌ 不做云同步、账号体系（本地优先是差异化定位）

---

## 3. 用户画像与核心场景

> **画像**：应届/在校求职者，同时投递多家公司，网申系统字段多、顺序各异、常带字数限制；简历源文件为 Word/PDF。

**核心场景循环**：

```
打开网申页 → 逐字段填表（复制 PinBoard → 粘贴到表单，重复 N 次）→ 提交 → 换下一家
```

产品价值 = 让这个循环中每一次"复制 → 粘贴"的摩擦趋近于零。

## 4. 需求优先级总览

| 编号  | 需求           | 优先级    | 预估工作量 | 解决的问题    |
| --- | ------------ | ------ | ----- | -------- |
| R1  | 子区域（块内值片段）复制 | **P0** | M     | 错位点 1    |
| R2  | 搜索过滤         | **P0** | S     | 错位点 2    |
| R3  | 字符计数         | **P0** | S     | 错位点 6    |
| R4  | 窗口位置持久化      | P1     | S     | 重启后窗口归位  |
| R5  | 最近复制置顶       | P1     | S     | 重复字段高频复制 |
| R7  | 分组 / 多套方案    | P2（暂缓） | L     | 多岗位多版本简历 |
| R8  | 贴边收纳         | P2     | M     | 非填表时段占屏  |
| R10 | 最近复制与源对账     | P2     | S / L | 改删后历史过期  |

> 工作量：S ≈ 半天内，M ≈ 1–3 天，L ≈ 一周以上（含适配与测试）。
>
> 错位点 3（录入成本）、4（开箱体验）、5（隐私暴露）目前没有对应需求：错位点 3 的常规路径已由 R1 的「整段 → 子区域」切换覆盖（按空行 / 逐行机械切分）；错位点 4 原由「网申简历模板」承接、5 原由「敏感信息打码」承接，两项均已移出范围。
>
> R6（全局热键速存）、R9（数据导出导入）已移出范围，编号不回填：R7 之后的编号在已发布版本说明、开发记录与风险表中已固定指代，重排会让它们错位。R9 移出的原因：设置页的「数据文件路径」已能直接定位数据文件，换机就是复制该文件、在新机器上改一次路径，不需要额外的导出 / 导入。
>
> R7（分组 / 多套方案）暂缓，不做排期：工作量 L，且要动数据结构、为 v1 平铺数据写迁移，收益只体现在多岗位并行投递的用户身上。

## 5. 需求详述

### 5.1 P0 — 已交付

#### R1 子区域（块内值片段）

**描述**：块内支持多个「子区域」，每个子区域是一段独立的值文本（单行或多行皆可）。软件对内容零假设——不解析语义、不加标签，复制什么完全由用户存的内容决定。

**数据模型**：

- `Block` 增加可选字段 `subRegions?: string[]`；存在时块以子区域模式渲染
- v1 纯 `content` 块不做迁移、行为零变更

**展示与复制**：

- 子区域之间以实线分隔；悬停反馈为整行底色 + 左侧强调条，光标为 `copy`（不常驻任何复制图标）
- 单击子区域内任意位置 → 复制该子区域完整内容（含换行）；复制成功的反馈是「颜色信号 + 一次性文字气泡」，**两条都不得碰到被复制的这一行**——值的可见性是置顶面板的意义所在，任何遮挡、替换、整行铺色都属倒退
  - 颜色信号：左侧绿色强调条 + 一道从左淡出的洗色，1.1s 后消失，文字一字不动
  - 文字气泡：绿色「已复制」，挂 `body` 用 `fixed` 定位浮在该行**下方**（挂在行内会被限行容器的 `overflow:hidden` 裁掉，也会遮住本行内容），1.2s 后自动消失；贴近视口底部时翻到上方，滚动即撤
- 子区域整体受本区域「显示行数」限制，与纯 `content` 块共用同一套折叠逻辑：溢出 → 底部淡出 + 折叠/展开按钮。行高固定、分隔线用绝对定位绘制，保证「N 行 = N 个行高」，不在折叠时少算可见行
- 与原生选区共存（判定时机 pointerup）：存在非空文本选区 → 判定为部分复制意图，不触发整段复制，交由 `Ctrl+C` 处理；无选区但指针位移 ≥ 4px（手抖容差阈值）→ 判定为拖动，同样不触发；双击保留原生选词
- 子区域不参与拖拽排序；块排序仍从标题 / 空白处发起

**编辑态**：

- 子区域支持增、删、改、上下排序
- 多行文本可直接作为一个子区域保存，不强制拆分
- 每段一张卡片，高度只服务于内容：序号在左、文本占满、操作按钮悬停浮现于卡片右上（一行文本的卡片约 44px，不常驻按钮行）
- 工具条显示条件：悬停该段**且未进入编辑**时显示；光标已在输入框内（正在编辑）时隐藏，避免遮住该段右侧内容。键盘 Tab 进入工具条时同样显示
- 「转为子区域 / 转为整段文本」共用同一枚按钮，放在**顶部工具区保存按钮左侧**（两种模式共用同一定位，图标表达目标形态，动作名交给气泡）；底栏回归「显示行数」单独左对齐
- 切换双向无损

**整段文本 ↔ 子区域互转规则**（双向对称，保证往返稳定）：

- 子区域 → 整段（编辑器内切换）：各段以空行（`\n\n`）拼接——空行是分段边界，保证反向自动分段能还原
- 点标题复制整块：各段以**单换行**（`\n`）拼接。与上面刻意不同——复制结果多半直接贴进表单，空行会变成多余段落间隔；这条只影响复制，不影响互转往返
- 整段 → 子区域：纯结构切分，不做语义识别，命中即停
  1. 存在空行 → 按空行分段（连续空行视为一个边界），段内换行保留
  2. 无空行且多行 → 逐行分段（简历常见「一行一项」）
  3. 单行 → 整体作为唯一子区域

**验收标准**：

- [x] 多行子区域一次点击复制完整内容（含换行）
- [x] 复制反馈期间被复制的值**始终完整可读**，无遮挡、无替换、无整行铺色
- [x] 复制成功同时给出绿色「已复制」气泡，位于该行下方，1.2s 内自动消失且不残留
- [x] 拖选子区域内部分文字后 `Ctrl+C`，仅复制选中部分，未触发整段复制
- [x] 子区域块受「显示行数」限制，溢出时淡出且可折叠/展开，与纯文本块表现一致
- [x] 整段转子区域后多次互转内容无损（分段边界稳定）
- [x] 编辑态一段文本的卡片高度 ≤ 48px，多段可在一屏内浏览
- [x] 纯 `content` 老块既有行为零回归

#### R2 搜索过滤

**描述**：顶部搜索框，按关键词即时过滤块列表。

**功能要点**：

- 匹配范围：标题 + 全部内容（含所有子区域），不区分大小写
- 关键词按空白拆分为多个词，**全部命中才算匹配**（AND）：`实习 字节` 比单字更精准
- 即时过滤（输入即生效，无确认按钮）；全量重绘后自动还原焦点与光标位置
- 输入法组合期间（中文拼音中）不重建列表，避免打断输入
- 无结果时给出空态：说明匹配范围 + 「清除搜索」直接动作，而不只报 0 条
- 清空关键词恢复完整列表；清除按钮、`Esc`、`Ctrl+F` 全选后直接覆盖输入，三种路径等价
- 过滤状态不持久化，重启后复位
- 快捷键 `Ctrl+F`（应用内）聚焦搜索框并全选；设置页 / 编辑态无搜索框时不拦截
- 过滤态下禁用拖拽排序：被隐藏的块不可见地挡在中间，换位结果无法预期
- 过滤态下新增块自动清空搜索，避免新块不匹配当前关键词而"建成即消失"

**验收标准**：

- [x] 30+ 块场景下，任意字段 ≤ 2 次交互（聚焦搜索 + 点击行复制）完成复制
- [x] 过滤中新增/编辑块后列表状态正确
- [x] 子区域内文本可被命中（`Raft` → 「项目经历」）
- [x] 过滤态下拖拽被拦截，非过滤态拖拽正常（对照组验证）

#### R3 字符计数

**描述**：块级字符数可见，辅助用户判断能否贴入限长表单。

**功能要点**：

- 展示态：块标题栏右侧显示块总字符数；含子区域的块在悬停子区域时显示该子区域字符数（网申限长针对单字段）
- 编辑态：输入框实时计数；整块总数在底栏，每段字数浮在该段卡片右上角，指针压到数字本身时淡出（要看被它盖住的字，把指针挪上去即可）；未聚焦的段在指针进入卡片时让位给操作按钮
- 显示格式固定为「当前 / 最近上限」（100/200/500/800），跨档只换数字不换写法；超过 800 变色提示
- 统计口径：按字符计（含换行），与主流网申系统一致
- 设置页切换"字符 / 不含空格字符"本次不做：口径固定为"按字符计"，等多一种真实需求再加，避免为一个未验证的选项增加设置项

**验收标准**：

- [x] 展示态与编辑态计数一致
- [x] 计数不引起布局跳动（固定占位）

### 5.2 P1 — 已交付

#### R4 窗口位置持久化

**描述**：窗口 x/y 随宽高一起保存，重启恢复到用户摆放的位置。

**功能要点**：

- 移动 / 缩放停止后记录位置与尺寸（400ms 防抖），关闭窗口前补记一次；最小化期间不记录（系统会把窗口挪到屏幕外）
- 位置以物理像素与尺寸一并存入 `WindowConfig`，旧数据缺省该字段即为「未记录」，首次启动仍居中
- 启动时恢复位置；左上角不落在任何显示器内则放弃恢复（拔副屏 / 改分辨率后回到默认居中）

**验收标准**：

- [x] 拖到副屏 → 重启仍在副屏原位置
- [x] 拔掉副屏后启动，窗口不出现在屏幕外

#### R5 最近复制置顶

**描述**：顶部出现最近复制动态分区，自动收纳最近复制的条目。分区不带标题，靠底色与边框与下方区域区分，省出一行高度；没有记录时整块不占位。记录随数据文件一同落盘，重启后原样恢复。

**功能要点**：

- 与区域数据同存于一份 `AppData`（`recent` 字段）：最多 5 条，同文本去重，超出丢最久未复制的；顺序为最近复制倒序，从区域/子区域复制时把该条提到最前
- 条目两段式：左侧是来源（区域标题，子区域再带 ` · 01` 段号），右侧是内容首个非空行；来源超长按窗口宽度截断，不撑破窄窗
- 单击条目复制内容，复制后不重排列表——否则点完立刻跳位，「已复制」气泡也落不到被点的条目上
- Ctrl+单击只复制所属区域标题（子区域同样只给标题，不带段号）；区域没有标题时提示「暂无标题」
- 拖选不触发复制（位移 ≥4px 判为拖选），交给原生 Ctrl+C；键盘 Enter/Space 等价单击、Ctrl+Enter 复制标题
- 悬停条目：底色 + 左侧 2px 蓝色强调条，与子区域一致；光标为 `copy`，按住 Ctrl 时切换为手型
- 复制成功在被点条目下方浮出「已复制」气泡（贴视口底部时翻到该条目上方），约 1.2s 自动消失
- 设置页可开关该分区显示；开关只控制显隐，记录继续保留并在隐藏期间继续累积，重新打开后原样显示

**验收标准**：

- [x] 复制某条子区域后它出现在顶部分区，单击该条目即完成复制，无需先展开分组或滚动定位（点击到复制成功 = 1 次点击）
- [x] 同文本只占一个位置，最多 5 条，超出挤掉最久未复制的；从区域/子区域复制时该条提到最前
- [x] 单击第 N 条，「已复制」气泡出现在第 N 条下方，列表顺序不变
- [x] Ctrl+单击只复制区域标题（子区域不带段号）；拖选文字不触发复制且可正常 Ctrl+C；区域无标题时提示「暂无标题」
- [x] 重启应用后条目内容与顺序原样保留（仍不超过 5 条）；关闭开关只是隐藏分区，重新打开后条目原样回来，重启后依然如此

### 5.3 P2 — 已实现与暂缓

#### R7 分组 / 多套方案（暂缓）

支持多套方案（如 `技术岗-中文` / `产品岗-中文` / `外企-英文`），顶部方案切换；块归属单一方案。数据结构升级需兼容 v1 平铺数据的自动迁移。当前不做排期。

#### R8 贴边收纳

**描述**：窗口拖到屏幕左右边缘后自动收成一条细边，把屏幕让出来；指针移上去立即滑出还原。收起只是形态变化，不动用户的尺寸、透明度与内容，记住的是「贴在哪一侧」而不是某次具体坐标。

**功能要点**：

- 拖到左右边缘松手即吸附，上下边缘不收纳；展开后拖离边缘即解除收纳，下次启动不再贴边
- 收起后留约 10px 淡色细边贴住屏幕边缘，高度不变
- 指针压上立即滑出，离开约 0.5s 收回；过渡约 0.2s，滑出减速、收回加速
- 展开后尺寸不变；原位置若露出屏幕，夹回可见区域
- 贴边侧记进配置，重启仍停在同一侧；展开位置失效（拔副屏、改分辨率）时改为居中展开并解除收纳
- 点任务栏图标、Alt+Tab 切回时自动展开；收起时先把前台交还，否则点击会命中「最小化当前窗口」
- 鼠标穿透开启时不收纳：先展开并保持，关闭后恢复待命、指针不在窗口内即收回；穿透下重启仍记住贴边侧，但启动即展开、不贴边（设置页的临时暂停同理）
- 编辑中不自动收起
- 多显示器按窗口所在屏幕判定，副屏边缘同样可吸附

**数据模型**：

- `WindowConfig` 增加可选字段 `docked?: DockSide`，取值为 `"left"` 或 `"right"`，存在即表示用户希望贴在该侧
- 缺省即未收纳，旧数据不做迁移、行为零变更
- 展开态的尺寸与位置仍用原有的 `width / height / x / y`；收起成细边时产生的那套几何不写回配置，展开时用内存里的快照还原
- 穿透开启时 `docked` 保留但不生效，启动时按普通窗口展开

**验收标准**：

- [x] 拖到左 / 右边缘松手收成细边，贴边侧与屏幕边缘齐平；指针压上去立即展开，离开约 0.5s 收回
- [x] 收起再展开后尺寸不变；位置在整窗可见时回到原处，原位置超出屏幕时被夹回可见区域
- [x] 收着窗口重启，仍停在同一侧细边
- [x] 展开位置已不在任何显示器上（拔副屏、改分辨率）时改为居中展开并解除收纳
- [x] 拖到上下边缘、拖到屏幕中间都不触发收纳；展开后拖离边缘即解除，重启不再收起
- [x] 副屏边缘同样可收纳，主屏窗口状态不受影响（需双显示器）
- [x] 贴边收起时点任务栏图标或 Alt+Tab 切回，面板展开
- [x] 开启鼠标穿透时自动展开且不再收纳；关闭穿透后恢复贴边待命，指针离开窗口即收回；开着穿透重启，贴边侧仍记住
- [x] 过渡顺滑无跳帧，不与拖拽、悬停样式互相打断

验证环境为单显示器 2560×1440：「位置失效回退」用把 `x` 改到屏幕外等价复现（居中展开 486×582、`docked` 置空）；副屏吸附与跨屏夹取只有 `cargo test` 的 DUAL 用例覆盖（`keeps_position_inside_secondary_screen` / `snaps_straddling_window_to_larger_monitor` / `drops_position_after_secondary_removed`），真机拖拽待双屏补验。

**已知限制**：

- 贴边时窗口的真实宽度就是 10px，任务栏悬停预览只能照出这条细边，点图标时的最小化动画也只是细边缩向图标。要让预览显示完整面板，得保持窗口宽度、再用系统级区域裁剪只留可见部分，与 WebView2 的合成机制容易冲突，本轮不做

#### R10 最近复制与源对账

最近复制存的是复制时刻的快照（`text / label / title`），与区域没有任何引用关系，源数据改动后不会同步：改内容后旧值仍可被复制（静默给出过期文本），同一字段的新旧两份各占一格；改标题后标签与 Ctrl+单击复制的标题都停在旧值；删区域后条目变成无源幽灵；子区域上移 / 下移后 `· 01` 与当前段号错位。

**做法**：文本级对账。启动与每次保存前，把条目按 `text` 与当前所有复制源（每个块的整块文本、每个子区域的文本）重新匹配一遍——命中则保留并把 `label / title` 刷新为当前标题与段号，未命中即删除。不动数据模型，条目仍是纯文本快照。

**已知取舍**：改一个标点条目也会消失，需要重新复制才回来。换来的是任何时刻都不会给出过期文本，也不会留下无源条目。

**验收标准**：

- [x] 改区域内容后保存，对应条目消失，不会被再次复制到过期文本
- [x] 改区域标题后保存，条目标签与 Ctrl+单击复制的标题同步刷新
- [x] 删除区域后，其条目随之消失；子区域删段后剩余段号重排正确
- [x] 子区域上移 / 下移后，`· 01` / `· 02` 与当前顺序一致
- [x] 文本未变的条目保持原有顺序与位置，不因其他区域改动被挤掉或提前
- [x] 启动时即完成对账：上次退出后源数据已改动的条目不会带着旧值复活
- [x] 关闭「最近复制」分区只影响显示，条目照常对账，重新打开后无过期项
